## 部署、升级与恢复

<a id="deployment-当前-compose-基础"></a>

### 当前 Compose 基础

Linux / Docker Compose：Nginx → Next.js / FastAPI → PostgreSQL 持久化卷。只暴露 Nginx；数据库和后端没有宿主端口映射。migrate 服务成功完成后启动后端，再经健康检查启动前端。管理员通过独立交互式 CLI 初始化，服务启动不自动创建管理员或业务数据。

运行 `python3 scripts/init_env.py` 生成权限0600的本机 .env；数据库密码随机生成，不回显，不覆盖已有配置。默认仅127.0.0.1:8080、HTTP与非Secure Cookie，用于本机验证。局域网正式使用必须配置 TLS 终止、APP_ORIGIN、SECURE_COOKIES=true 和适当的绑定地址；当前 Nginx 示例尚未包含证书管理。

后端及前端容器使用非root账号。数据库初始化用户当前也是schema所有者，因此尚未满足生产最小权限角色隔离。生产上线前需拆分迁移所有者与应用角色，演练最小权限、恢复与外部审计锚定。

Redis、Celery 和 outbox 在需要后台任务时随对应模块加入，Phase 1 核心不依赖它们。构建阶段需要下载依赖，构建后的核心运行不需要第三方云服务。

<a id="deployment-备份与恢复"></a>

### 备份与恢复

使用 pg_dump --format=custom 备份。恢复前停止写入并保存当前备份，在独立数据库中使用 pg_restore 验证，核对 Alembic 版本、行数与审计链；库存模块加入后还必须核对流水和余额。不得未经确认覆盖生产数据库。密钥、附件和配置另行加密备份，定期实际恢复演练。

### 本机验证范围

本机无 Docker，未执行 docker compose build/up 或备份恢复演练。已通过项目内真实 PostgreSQL 18.4 的迁移、认证、权限、审计和并发测试；这不能替代 Compose 中 PostgreSQL 17 的镜像启动与部署验证。

<a id="deployment-采购资料基础迁移"></a>

### 采购资料基础迁移

5a6ef43a4a48为新增迁移，不修改前两份迁移。请先备份并在数据库副本验证升级，再执行alembic upgrade head。迁移不改变旧策略权限；管理员在权限中心明确授权categories、suppliers、warehouses及products.category_id。配置表的币种为空、税模式未配置、独立审批人为true；目前已开放采购业务，使用前需明确授权与配置。

迁移降级只允许新业务表为空且没有v2审计事件的数据库；运行新应用后通常会产生v2审计，因此不能把downgrade当成通用业务回滚。代码回滚和恢复数据库应使用经过验证的一致性备份方案，恢复演练尚未完成。本变更不声称支持在线无停机迁移。

采购MVP服务现已开放，但已有策略不会自动获得新权限。管理员需在权限中心明确配置采购资源、warehouses.receive及采购金额字段组，再进入“采购业务规则”明确支持币种与无税模式。默认保留独立审批人，由另一个有approve权限的账号审批；不自动关闭该限制。退货、冲销、含税和汇率换算尚不支持。outbox尚无通知消费者，采购成功不代表外部通知已发送。

### v1.0.5 升级与恢复

### v1.0.9 AI升级与可选启用

若需启用，由部署管理员设置`AI_ALLOWED_BASE_URLS`为精确兼容Base URL的JSON数组，例如`["http://127.0.0.1:11434/v1"]`；容器中127.0.0.1指容器自身，须按实际网络填写可达地址。需要认证时配置服务端`AI_API_KEY`，无需认证的本地服务可留空。不要把凭据放进URL、客户端或仓库。`.env.example`和Compose已预留这些可选项，核心服务不依赖外部模型。

管理员随后在Web「AI 服务配置」选择允许地址、模型名称、2至20秒超时和工具，再启用。普通用户需ai_requests相应动作、主资源ai_query与read；销售汇总还需report。旧策略不自动扩权。保存配置会令旧解析版本不能确认，须重新理解。

本版用回环HTTP测试服务验证协议、超时、拒绝和真实业务查询，没有配置生产供应商或调用付费模型；上线前需验证所选服务支持chat/completions及JSON格式参数、TLS/网络出口、密钥管理与文本保留政策。HTTP应限可信内网，公开网络优先HTTPS。生产Linux/Compose启动与备份恢复仍未验收。

## 安全边界

Argon2id 密码、随机服务端会话、token/CSRF 仅存摘要、即时用户禁用与会话撤销。失败登录按来源限流并按账号锁定，所有入口通用。
Cookie 默认 Secure/HttpOnly/SameSite=strict；局域网生产部署 TLS。开发模式显式关闭 Secure 时仅供本机。禁止通配 CORS，写请求校验 Origin 和 CSRF。

权限引擎为最终边界，管理员角色名称无特殊逻辑。策略中不能出现代码。审计追加哈希链与 PostgreSQL 禁止修改触发器；数据库所有者不在防篡改保证范围内，需离机锚定。错误审计只记录路由、状态、trace，不记录输入密码和 token。

API Key 不提交、不回显；通过服务器环境/受限 secret 文件配置。AI 默认关闭。外网发布、正式 release、破坏性恢复需显式操作授权。

上线前必须完成 PostgreSQL 并发、TLS、备份恢复演练与应用角色最小权限验证；本开发阶段不宣称已达成生产安全认证。

采购：收货命令的身份、所有者/部门、关联数据及操作权限来自当前会话和数据库。禁止客户端提供采购所有者、状态、总额和库存余额。相同幂等键不复用不同命令，回执重新投影，撤权后的重放拒绝。金额、行金额和单价联动隐藏/脱敏；关联权限在分页之前编译进SQL。游标仅作用于ID可读记录。

普通业务异常/校验失败回滚后单独追加失败审计，未预期异常在数据库可用时记录500；数据库不可用时保留脱敏追踪日志，需后续外部告警与审计锚点。SQLAlchemy启用hide_parameters，不在异常信息中输出绑定参数。

<a id="security-v103-消息边界"></a>

### v1.0.3 消息边界

反向WS拒绝查询参数令牌、浏览器Origin、错误bot标识和非Universal连接。实例随机令牌仅存摘要；轮换/停用后每帧重查。平台sender.role不授予ERP权限。绑定须Web密码复核、指定平台账号及5分钟单次挑战，兑换时重查当前策略/用户；群聊不兑换、不查询、不回复。

消息只读工具复用Web的SQL范围和字段投影，搜索字段不可读时不参与匹配。消息原文、密码、令牌、绑定码和结果不写入审计或收件箱。收件箱数据库防修改、Gate与唯一键保证重复处理安全；失败回滚再记脱敏审计。限流当前为每实例300/分钟、每平台用户30/分钟。

连接令牌持有者代表受信OneBot源，须保护适配器主机。当前未对OneBot API回复确认、外部QQ链路和生产部署作保证；消息写入与高风险动作未开放。

<a id="security-v104-请求确认"></a>

### v1.0.4 请求确认

请求仅保存白名单采购参数，原始消息、连接令牌及密码不入库。确认摘要覆盖预留订单ID、归属、标准化金额/数量、引用资料ID/版本和绑定版本。参数或资料变更后旧确认失效；解绑再重绑不恢复旧会话。每次确认/重放均需要当前Web会话、CSRF和密码复核，消息中的确认命令不能创建订单。

预览无业务写入；只有显式Web确认才调用原采购服务。订单、会话完成、outbox与审计原子提交，失败不留下半成品。数据库约束强制等待/完成态摘要、完成结果与预留订单一致、绑定快照成对存在。权限不足不返回旧预览、旧结果或隐藏ID；重名和不可见引用共用错误提示。

<a id="security-v105-消息投递"></a>

### v1.0.5 消息投递

队列持久化受限recipe，不存完整回复、原始消息、密码、访问令牌或平台错误正文；终态清除recipe。绑定ID/版本、主体与收件人必须同时匹配，每次尝试重新授权和投影；延迟回复不能沿用撤权前的数据。连接UUID、当前实例配置和90秒租约形成隔离边界，旧连接不能确认或清理新连接。回执必须匹配当前尝试的echo和连接；异步回执不表示成功。接口没有强制补发或修改队列状态能力。OneBot不提供发送幂等键，故业务去重不等于回复恰好一次。

<a id="security-v106-销售边界"></a>

### v1.0.6 销售边界

销售与采购共享Gate、当前身份/策略和审计事务，客户/商品关联范围在SQL分页前校验。销售金额字段共同脱敏，状态/ID筛选要求字段可读。客户端不能指定销售订单归属、总额或审批人；销售始终阻止创建人自批，含待审批策略不直接执行。销售尚未接入消息/AI工具，不扩大既有受控查询白名单。新建销售不改变库存，后续出库需单独审计与并发验证。

<a id="security-v107-出库保护"></a>

### v1.0.7 出库保护

出库先合计重复商品需求，再按稳定顺序锁余额；禁止负库存、超计划和已发订单直接取消。后端仅接受现有订单行、数量和仓库，主体/归属/状态由服务器产生；CSRF、Gate、旧/新状态、字段/范围和requires_approval均约束执行。库存数量不可读时不执行可探测的扣减比较。

相同幂等键与规范化参数只回读已存在发货单；当前授权失效则拒绝，不重放业务。发货/明细/执行记录和库存流水不可变，kind与唯一来源配对。Web网络结果不明时保留原请求重试；真实浏览器验证已提交后断响应再重试仅扣一次。退货/冲销、成本/批次与消息直接出库未开放。

<a id="security-v108-聚合与csv"></a>

### v1.0.8 聚合与CSV

报表依赖当前Gate/策略及既有业务查询的关联范围。可读字段不足的记录在筛选、数量与金额聚合前排除，不通过总数、分组、排序恢复隐藏值。导出额外要求export，权限撤销后重新计算；前端重验证和错误时隐藏旧结果。

来源和分组上限整体拒绝，SQL超时保护，CSV危险公式前缀转义，固定文件名/no-store响应。审计仅记录报表、指标、合格行数、过滤字段名及策略版本，不写业务单元格或金额。浏览器已下载文件的后续管理属于企业运维范围，撤权不会删除历史下载。详见[报表边界](BUSINESS.md#reports)。

<a id="security-v109-ai安全边界"></a>

### v1.0.9 AI安全边界

默认关闭、逐次明确同意、部署端精确URL白名单、禁用重定向及环境代理，密钥仅服务端SecretStr环境配置。HTTP仅用于管理员明确允许的可信网络；白名单域名的DNS与出口边界由运维控制，不宣称实现DNS固定或全网SSRF防护。模型端点故障不影响离线业务。

不信任模型输出：严格schema、extra=forbid、受限字符串参数、有限置信度、重复JSON键拒绝、32KiB响应上限、总超时、拒绝截断/refusal/tool_calls。模型只能建议白名单只读意图，不能指定用户/角色、SQL、代码、网络目的地或写入动作。

模型调用期间释放Gate；完成/查询时重新认证原会话并重查配置、权限、租约与状态。工具为read∩ai_query，报表再加report，当前字段脱敏/拒绝不能被AI绕过。原输入和响应不入库/审计，只有已校验意图持久化；API Key只通过允许端点的Authorization头发送。业务结果不回传模型。参数解析前失败审计补偿与事务错误标记防止漏记/重复记录，日志不包含输入正文。

### v1.0.10 采购意图隔离

AI采购仅单商品参数，未知身份/SQL/状态/执行动作及无效数值严格拒绝；与离线解析和Web共用纯参数校验。供应商/币种不猜测，低置信度不能通过本地修改提升。固定期限与10轮补全限制，不存原文或把补充值返回模型。原会话与当前权限/配置/版本持续检查至用户明确移交；一次待确认请求与源版本同事务，失败全部回滚。移交后为普通人为流程，关闭AI不取消已有请求，当前业务撤权仍阻止确认；只有密码确认可创建草稿。
