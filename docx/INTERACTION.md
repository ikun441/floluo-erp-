## 离线指令

v1.0.5在v1.0.4基础上增加离线规则。固定命令优先，失败的`/`命令不会退回自然语言猜测；其余文本仅匹配完整的有界句式。没有网络、模型或数据库依赖，不支持的描述返回未识别，不会自动调用AI。

<a id="offline-支持的表达"></a>

### 支持的表达

- `查询一下鼠标还有多少库存。`、`查询鼠标库存`、`鼠标还有多少库存？`，可加「请」「帮我」。
- `查询采购订单`或`查询采购订单 PO-单号`，最多返回当前授权范围内20条。
- `登记采购20个鼠标，每个35元。`，缺失供应商和币种，进入待补充请求。
- `采购2.5件"Mouse A"，单价12.50元，供应商="Supplier A"，币种=CNY。`，使用单商品、显式供应商与币种。
- 固定命令仍可使用，新增可选`单位=个`。普通Web表单不填写单位时沿用商品基础单位。

商品/供应商名称、ID或编码只由后续业务服务按当前可见字段唯一解析；解析器不从数据库猜实体。引号包围的名称作为一个字面实体；未引号包围的「和/及/与/或」等连接词及多动作文本拒绝。仅支持阿拉伯十进制数字，不转换中文数词、包装单位、汇率或税额。

数量保留4位、单价2位上限，继续使用Decimal规则。自然语言中的单位必须保留进请求payload，完整预览和确认时要求商品unit当前可读且完全相同。`2箱/每个`语义不一致拒绝；`公斤`与`千克`不自动视为同义，商品为piece时不能静默把「个」换过去。「元」不代表默认CNY，币种必须明确提供。

<a id="offline-web和消息边界"></a>

### Web和消息边界

协议无关的`erp.intent`定义BusinessIntent与固定命令；`erp.local_parser`输出相同operation/resource/arguments/references/confidence/parser_source。`erp.onebot.intent`保留兼容导入。confidence仅为确定规则的来源分数，不代表业务授权或允许执行。

Web操作工作台新增「用一句话开始」：识别 → 展示结构化结果 → 明确执行授权查询或生成待确认请求 → 原有业务预览/密码确认。编辑描述立即丢弃旧识别与查询结果；每次动作由后端重新解析，客户端不能提供角色、工具名称或可信授权结果。查询复用Web/OneBot的SQL范围与字段投影；创建复用持久化MessageOperation服务，没有直接创建订单的新通道。

消息入口仍要求受信实例、有效绑定、bindings.use和业务策略；群聊无业务回复或执行。重复事件沿用收件箱去重。采购描述仅创建待补充/待确认请求，补充、取消、超时及Web密码确认规则保持不变。

<a id="offline-解析请求的数据与审计"></a>

### 解析请求的数据与审计

解析部分无需修改原数据库结构：已有JSON payload新增可选unit白名单键，旧请求保持可读；本版本投递队列使用独立新迁移，见DELIVERY.md。HTTP输入最多4096字符、拒绝额外键；本地自然语言拒绝换行与控制字符。原始描述、身份信息、密码和外部模型配置不会写入审计，仅记录现有路由/操作状态和安全元数据。解析本身只生成惰性结果，除审计外不写业务表。

本阶段不支持自由自然语言补充、多商品描述、主动OneBot连接、AI回退或通用审批。无法识别时继续使用固定命令/表单，不对用户进行猜选或伪成功。

<a id="operations"></a>

## 操作工作台

v1.0.4同时提供Web发起入口和OneBot固定命令入口，复用同一持久化请求、权限引擎、采购校验与事务服务。请求不是订单；只有在Web预览并复核密码后才创建采购草稿，后续提交、独立审批与入库继续走已有采购流程。

<a id="operations-使用流程"></a>

### 使用流程

1. Web「操作工作台」发起采购请求，可只选择部分信息；选项来自当前授权的前100条商品/供应商。也可私聊已绑定OneBot实例发送 `/erp 采购 新增 商品=可见编码 数量=2 单价=12.50`。
2. 待补充请求可通过Web详情补充，或发送 `/erp 补充 请求ID 供应商=可见编码 币种=CNY`。只更新明确提供的字段，未知键、重复命令参数、非法精度和客户端身份字段拒绝。
3. 完整参数必须解析为唯一且可见/启用的商品与供应商。支持可读ID、编码或名称；重名、无权限或不存在时使用同一拒绝提示，不猜选记录。草稿预览使用与真实采购相同的无写入计划，金额使用Decimal。
4. Web显示当前授权预览；确认者需要看见全部关键金额字段，输入当前ERP密码，明确点击「确认创建采购草稿」。`/erp 确认 请求ID`只提示转Web，不执行创建。
5. 取消可使用Web按钮或 `/erp 取消 请求ID`；`/erp 预览 请求ID`读取当前授权详情。请求固定10分钟有效期，补充不会延长。每用户最多20条待处理请求；列表提供状态筛选、分页和当前状态。

<a id="operations-状态与一致性"></a>

### 状态与一致性

collecting_missing → awaiting_confirmation → completed；两个等待态可取消或过期。修改参数后重新生成预览摘要。资料版本、归属部门或绑定发生变化时，旧摘要不能确认，需刷新重新查看；若当前权限已不足，拒绝展示或执行。completed表示草稿已创建，不代表已审批或入库。

Web发起的请求归属当前会话用户，无平台绑定。消息发起请求保存绑定ID/版本，后续消息必须来自同一有效绑定；解绑、重新绑定或实例停用不会使旧请求重新可执行。Web可取消自己的旧请求以清理队列。

确认同时检查请求version、preview_digest、当前绑定、当前策略、资料状态/版本。采购订单/明细、会话完成状态、outbox和审计同事务；失败回滚。重复确认须再次复核密码和当前授权，仅返回现有草稿的当前投影，不重复创建。结果ID也受当前采购读取权限保护，不在任务列表中直接暴露。

过期在访问/处理时推进并审计，没有必需后台任务。数据保留后台、主动OneBot连接、自由自然语言补充、消息平台AI、通用审批及消息直接落单尚未实现。当前新增功能只创建单商品采购草稿请求，不支持自由操作类型、SQL或代码。

<a id="operations-升级授权"></a>

### 升级授权

升级不自动扩大旧角色权限。已有管理员在权限中心显式为目标角色添加message_operations：own范围，read/create/update/cancel/confirm；id/version/owner_id/binding_id/resource/时间/missing_fields/result/result_id可读，preview和state需write。还需原有采购create/read及商品/供应商读取权限；消息来源另需message_bindings.use。字段隐藏、金额条件、明确拒绝、requires_approval均继续生效；待审批规则不能由本工作台跳过。

密码复核每用户每分钟最多5次，失败累积至账号锁定。密码、原始消息和参数明文不进入操作审计。预览参数只以白名单业务JSON保存在受保护会话中。

v1.0.5扩展：工作台已增加离线指令助手，先识别并显示参数，再执行授权查询/生成请求。payload新增可选unit，不填时沿用商品基础单位；自然语言会显式保留单位，完整预览和确认必须核对当前可读unit，不做单位换算。规则详见INTERACTION.md。

## AI配置、解析与查询

<a id="ai-当前已实现范围v1010"></a>

### 当前已实现范围（v1.0.10）

AI默认关闭；支持受控只读查询及单商品采购参数预览/人工移交。离线固定命令/本地规则始终优先；本地已识别的描述不会调用模型。用户明确同意后，仅发送本次输入与静态意图格式，不发送任何数据库记录、用户角色、业务配置或隐藏字段。模型只生成标准结构化意图，返回后还需用户确认查询；模型输出不执行SQL、代码或写入业务。

<a id="ai-数据关系编写业务代码前确认"></a>

#### 数据关系（编写业务代码前确认）

| 表               | 关键字段                                                                                                                                    | 关系/用途                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| ai_configuration | id=1、version、enabled、base_url、model、timeout_seconds、tools                                                                             | 单企业可选模型配置，默认关闭；不保存API密钥                                                              |
| ai_request       | id、version、owner_id、session_digest、config_version、request_key、payload_digest、state、intent、error_code、expires_at、lease_expires_at | owner→erp_user，session_digest→session_token；只保存校验后的意图，不保存原始描述、模型原始响应或查询结果 |

新增独立df2b1c0d9e8f迁移，不修改已发布迁移。用户与request_key唯一，原描述/同意/配置版本摘要绑定参数；同一会话相同键重试只返回当前可见请求，不重复调用模型，参数冲突409，处理中409，过期租约回放转失败。请求状态为parsing→ready/clarification/failed，用户可取消；过期按服务端UTC判断。低置信度仅提示重写，不能执行。解析租约限制同时进行的模型请求：每用户1个、全企业2个，另外每用户每分钟最多5次。失败和进程崩溃后的租约不会永久占用配额。

<a id="ai-依赖与事务"></a>

#### 依赖与事务

Web→ai_api→ai_service→白名单HTTP模型适配器或ai_gateway→原业务服务/权限引擎→数据库。初始授权、模型完成后保存、确认查询分别使用短Gate事务；模型网络调用期间没有数据库事务或Gate锁。完成后重新检查原会话、用户、当前策略、配置版本/开关、租约和请求归属。超时/取消/停用/撤权不会执行查询。模型不可用不影响传统ERP。

<a id="ai-授权"></a>

#### 授权

ai_configuration支持read/update；ai_requests支持read/create/execute/cancel/update/prepare且永远额外限定当前用户与原会话。intent字段控制可写描述解析与可读预览，执行要求完整预览可读并检查execute。inventory_balances/purchase_orders/sales_orders增加独立ai_query动作。工具取read∩ai_query，行范围、字段最严约束、明确拒绝与待审批均生效；销售汇总另需report。关联资料沿用原Web可读约束，不能由模型提供user_id、role、SQL、代码、任意URL或扩大范围。

| 工具                  | 标准意图资源    | 应用服务                                                 |
| --------------------- | --------------- | -------------------------------------------------------- |
| query_inventory       | inventory       | 同Web/OneBot库存查询，最多20条、当前字段投影             |
| query_purchase_orders | purchase_orders | 同Web/OneBot采购查询，最多20条、金额字段联动             |
| query_sales_summary   | sales_summary   | v1.0.8销售报表服务，保留来源/字段/币种/规模与SQL超时约束 |

采购参数工具prepare_purchase_draft另见下方v1.0.10补全与移交章节；它只创建待确认请求，不通过查询网关执行业务写入。

工具结果直接展示给当前用户，不回传模型、不持久缓存。管理员工具开关只是上限，不能替代用户数据权限。确认查询重新检查策略和配置，不使用解析时的授权结果。查询为只读，重复确认重新查询当前可见数据。

<a id="ai-网络与密钥"></a>

#### 网络与密钥

部署侧AI_ALLOWED_BASE_URLS显式列出允许的兼容服务地址（JSON数组，默认[]）；Web只能选择该白名单中的地址。拒绝URL凭据、query/fragment、重定向和环境代理。HTTP端点也须显式列入白名单，应只用于可信内网；域名解析与网络出口由部署管理员管理，不在运行时猜测网络归属。API密钥仅从服务端AI_API_KEY读取，Web只展示是否配置，数据库/日志/模型输入不包含密钥；无需密钥的本地模型可留空。

兼容适配器使用chat/completions、json_object及明确JSON提示，仍对响应执行严格白名单schema校验，拒绝截断、refusal、tool_calls、未知参数、重复JSON键和非有限数。超时2至20秒、响应最多32KiB、无自动重试；失败只返回受限错误代码，不反射供应商响应。

协议参考：[OpenAI官方结构化输出文档](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=chat)。JSON mode不等于业务schema校验，兼容服务是否支持这些参数需真实联调验证。

<a id="ai-本阶段边界"></a>

#### 本阶段边界

不配置真实供应商或调用付费端点，使用隔离HTTP测试服务验证协议与真实业务查询；不声称模型语义准确率或生产模型已验收。采购仅支持本地结构化补充并人工移交，不自动执行业务。多轮自然语言模型调用、销售写入、OneBot AI接入、对话总结与更多工具留待后续版本。Harness仅用于开发辅助，不是产品AI运行依赖。

### 已实现 API

| 方法与路径                            | 用途                                                             |
| ------------------------------------- | ---------------------------------------------------------------- |
| GET /api/v1/ai/status                 | 当前登录用户读取开关状态，不暴露地址、模型或凭据                 |
| GET /api/v1/ai/configuration          | 按字段权限投影模型配置及部署允许地址                             |
| PATCH /api/v1/ai/configuration        | version + values，校验旧/新配置权限与乐观锁                      |
| POST /api/v1/ai/requests              | text + consent=true，必须提供ASCII Idempotency-Key（1至128字符） |

| GET /api/v1/ai/requests/{id}          | 当前会话的授权预览                                               |
| POST /api/v1/ai/requests/{id}/execute | version，重新授权只读查询，不调用模型、不缓存业务结果            |
| POST /api/v1/ai/requests/{id}/cancel  | version，取消并清除已解析意图                                    |

请求有效期5分钟，解析租约为配置超时加10秒。ready才可确认；clarification/failed/cancelled或过期均拒绝查询。模型请求完成后版本递增；重复查询仍检查当前原会话、配置版本、工具、范围及字段。

未授权403或范围内不存在404；禁用/处理中/参数摘要冲突/版本变化409；过期410；参数422；频率/容量429；模型不可用、响应校验失败或超时502。错误不会反射供应商正文。原会话已注销/用户停用时401，模型结果不会持久化为可执行预览。

原始描述仅存在本次调用内存及显式同意的模型请求中；校验后的intent可能保留商品关键词/单号，属于企业业务数据，应纳入数据库备份与历史保留管理。没有自动清理策略。模型服务的数据保留与网络出口须由部署管理员配置，不能以协议兼容性代替供应商验收。

<a id="ai-v1010-已实现采购参数补全与人为移交"></a>

### v1.0.10 已实现：采购参数补全与人为移交

本阶段增加单商品采购意图（create/purchase_orders），独立工具prepare_purchase_draft默认不启用。模型只提取arguments(quantity/unit_price/currency/unit)和references(product/supplier)，缺失值留空，不提供数据库实体，不产生业务记录。置信度不足不能经表单提升。高置信度的缺失字段可在本地结构化表单多轮补充，最多10次，固定5分钟有效，不再次发送模型。

关系：ai_request 1 → 0..1 ai_handoff → 1 message_operation。新表ai_handoff以request_id为主键/FK、operation_id唯一FK，保存移交前请求版本和时间；唯一约束与同一Gate事务防止重复创建待确认请求。旧表、旧策略及旧迁移保持不变。有AI解析历史拒绝回退该迁移，防止旧代码读取新意图。

权限：ai_requests增加update/prepare动作和operation_id虚拟字段，采购增加ai_prepare动作。补充与移交校验原登录会话、当前身份、请求版本/期限、配置版本/工具、原/新字段授权；移交时采购create∩ai_prepare约束作用于真实候选，引用资料和金额预览沿用操作工作台。查询execute不接收写入意图。旧角色不自动扩权。

状态：parsing → clarification（低置信度或参数缺失）/ready；高置信度clarification经本地补充可变为ready。ready → 用户明确移交（AI请求冻结参数，链接待确认操作）；重复原版本移交只返回同一操作，不能创建订单。移交后由操作工作台管理，不能再修改/取消AI源意图；普通请求的取消/超时与原密码确认仍有效。

API：PATCH /ai/requests/{id}补充{version,values}；POST /ai/requests/{id}/prepare带{version}，仅创建待确认请求。移交是用户接受结构化参数后转为普通人工流程的明确边界：后续可独立于AI开关运行，确认始终重新校验当前业务权限、引用版本、预览摘要并要求当前密码，最多创建一张采购草稿，不提交/审批/入库。

本阶段不增加对话原文存储或多轮模型调用，不支持多商品AI采购、AI审批、AI出入库或OneBot AI。后续可在逐次同意和明确上下文边界下扩展自然语言轮次。

使用步骤见[AI采购使用说明](INTERACTION.md#ai-purchase)。

<a id="ai-purchase"></a>

## AI采购使用步骤

<a id="ai-purchase-开始前"></a>

### 开始前

管理员需先启用可选AI服务、选择prepare_purchase_draft工具，并配置AI请求read/create/update/prepare、采购ai_prepare/create/read、商品/供应商读取以及操作工作台权限。旧角色不自动获得新动作；用户必须能完整看到待确认的金额与参数。

<a id="ai-purchase-描述与同意"></a>

### 描述与同意

在AI助手输入单商品采购需求。系统先使用离线规则，未识别时由你勾选同意，才将本次描述发送到企业模型。数据库记录与查询结果不会发送模型。识别结果只是待检查的参数，不能自动创建订单。

<a id="ai-purchase-分次补充"></a>

### 分次补充

检查商品、数量、单价、供应商、币种和可选单位。遗漏信息通过表单补充，可多次保存；每次重新显示当前结构化预览，不再次调用模型。名称必须精确且当前可读，重名时使用编码或ID。币种须明确填写，不自动把“元”换算为CNY，单位不自动换算。低置信度须重新描述，表单不能提升模型置信度。

<a id="ai-purchase-移交与确认"></a>

### 移交与确认

参数齐全后点击“确认参数并移交操作工作台”。这一步最多创建一个待确认请求，没有采购订单。页面直达该请求，再看当前授权的商品、供应商和金额；输入当前ERP密码确认后，仅创建一张采购草稿。提交、独立审批、入库仍按原业务流程操作。

移交后在操作工作台补充、修改、取消或确认。AI源参数冻结；关闭AI服务不会取消你已经明确接受的普通人工流程。撤销当前业务权限仍会阻止预览或确认。

<a id="ai-purchase-超时与重试"></a>

### 超时与重试

AI预览固定5分钟有效，本地补充最多10次且不会延长期限；操作工作台请求有自己的10分钟期限。网络结果未知时先刷新预览或操作列表，同一原版本的移交重试只返回原请求。商品资料变更导致摘要失效时，刷新预览重新确认。

本版本不支持多商品AI采购、自然语言连续对话、AI审批、自动出入库或OneBot AI。真实生产模型需单独联调。

## OneBot接入

<a id="onebot-v105-离线中文规则与可靠回复"></a>

### v1.0.5 离线中文规则与可靠回复

库存查询与单商品采购描述现可在绑定后的私聊使用，例如「查询一下鼠标还有多少库存」和「登记采购20个鼠标，每个35元」。明确规则匹配失败时提示固定命令/表单，不调用AI。供应商、币种缺失继续走补充流程，单位保留并在当前授权预览/确认时核对商品基础单位。详情见[INTERACTION.md](INTERACTION.md#offline)。Web操作工作台提供同一解析器的识别、结构化结果和受控执行入口。

连接与回复现在使用持久化recipe和单实例租约，支持回执、重连、有界重试及Web监控。每次发送重查当前身份与权限，详见[DELIVERY.md](INTERACTION.md#delivery)。

<a id="onebot-v104-采购请求与web确认"></a>

### v1.0.4 采购请求与Web确认

新增持久化采购请求：消息发起可先缺少字段，使用 `/erp 补充 请求ID 字段=值` 多轮补齐，`/erp 预览 请求ID`获取当前授权预览，`/erp 取消 请求ID`取消。请求10分钟有效，参数/资料/绑定版本变化后旧摘要失效。`/erp 确认 请求ID`只提示进入Web操作工作台复核密码，不能直接创建订单。

工作台支持Web发起、列表筛选/分页、当前预览、参数补充、取消、密码确认。预览复用无写入采购计划，确认只创建draft；仍需后续提交、独立审批和入库。消息来源保存绑定版本，解绑再重绑不能恢复旧请求。详见[操作工作台](INTERACTION.md#operations)，版本日志见[docx/version.md](version.md)。

<a id="onebot-连接基础始于v103"></a>

### 连接基础（始于v1.0.3）

支持反向 Universal WebSocket：OneBot 客户端主动连接 ERP 的 `/onebot/v11/ws/{instance_id}`。实例固定 bot ID，管理员在 Web「消息接入」创建实例后只收到一次随机访问令牌；数据库仅存 SHA-256 摘要。握手必须携带 `Authorization: Bearer <token>`、`X-Self-ID`、`X-Client-Role: Universal`。不接受 URL 查询参数或浏览器 Origin。令牌不能放在 URL、日志或策略 JSON 中。

协议参考：[反向 WebSocket](https://github.com/botuniverse/onebot-11/blob/master/communication/ws-reverse.md)、[鉴权](https://github.com/botuniverse/onebot-11/blob/master/communication/authorization.md)。配置 OneBot 使用 Universal 类型和消息段数组，断线重连由 OneBot 客户端发起。Nginx 已配置该路径的 Upgrade 转发；本机开发可直连后端8000端口，生产使用受信 TLS 的 wss 地址。

实例、绑定和业务权限均通过统一权限引擎配置。升级不会自动给旧角色增加权限。新安装 bootstrap 显式建立当前资源策略。已有管理员可在权限中心为实例管理员配置 `onebot_instances` 的 read/create/update/rotate_token，令牌字段 access_token 只能 hidden/write；使用者通常只需实例 id/name/bot_id/active/version 的 read，加 `message_bindings` 自身范围的 read/create/revoke/use，以及对应采购、商品、供应商、仓库和库存的业务读取权限。消息适配器不信任 QQ 群角色、客户端提供的 ERP 用户或部门。

<a id="onebot-绑定与撤销"></a>

### 绑定与撤销

1. 已登录 ERP 用户在 Web 选择可见且启用的实例，输入预期的 QQ 号与当前 ERP 密码。
2. 服务端复核密码及当前 create 权限，签发5分钟单次绑定命令；新命令使同一用户/实例旧挑战失效，数据库只存命令摘要。
3. 用指定 QQ 在相同实例私聊发送该命令。群聊不兑换。服务端再次检查目标 QQ、实例、有效期、当前用户状态和策略，再在同一事务中建立绑定、消费挑战并记录收件箱和审计。
4. Web 可撤销自身绑定；撤销后旧平台消息不再获得业务身份，同时使该用户/实例未消费挑战失效。停用或轮换实例令牌使已有连接在处理下一帧或60秒空闲检查时失效。

一个实例下，每个平台账号和每个 ERP 用户各有唯一绑定。撤销保留记录，允许原用户重新绑定同一平台账号；变更到其他账号/转移给其他用户仍拒绝，等待后续受审计的重绑定流程。仅掌握 QQ 号不能建立绑定；管理员配置的 OneBot 实例是受信的消息来源，需保护其主机和访问令牌。

<a id="onebot-消息解析与查询"></a>

### 消息解析与查询

协议适配器只接受有界纯文本消息段数组；匿名群消息、错误 bot ID、混合媒体、重复 JSON 键和超限帧拒绝。帧上限64KiB，文本上限4096字符。生命周期/心跳、notice、request 和 API 回执不进入业务解析器。

- `/erp 库存 查询 "Mouse A"`：在有 name/id 读取权限的商品范围中匹配名称，复用 Web 库存关联范围及字段投影，最多返回20条。
- `/erp 采购 查询 [单号]`：复用 Web 采购关联范围及金额投影，最多返回20条；按单号过滤前必须具备单号可读权限。
- `/erp 采购 新增 商品=mouse 数量=20 单价=35 供应商=example 币种=CNY`：仅生成受限结构化意图。缺失字段会明确返回；本版完整意图建立待确认请求，须通过Web预览及密码复核后创建草稿。

所有群聊业务消息均无回复、无业务执行；不会把私密结果发到群里。仅私聊且当前绑定有效、用户启用并具备 bindings.use 时可进入业务查询。权限变更、显式拒绝、字段隐藏/脱敏和需要审批的读取，均在当前数据库策略下重新判断；没有缓存旧数据供重放。

<a id="onebot-事务去重限流和审计"></a>

### 事务、去重、限流和审计

适配器调用应用网关，网关先锁 authorization_gate。稳定 event_key（实例、bot、聊天对象、发送者、message_id）作为收件箱主键，另保存 payload_digest；成功或拒绝、绑定变更、收件箱及审计同事务提交。重复事件不重复执行或再次发送旧结果，同键不同内容拒绝并断开连接。失败回滚不会留下半完成绑定；意外失败先回滚，再尝试单独追加失败审计。

收件箱采用数据库 UPDATE/DELETE/TRUNCATE 防修改策略（SQLite 不提供 TRUNCATE），不保存原文、查询结果、令牌或绑定码。实例每分钟300条、实例内单用户每分钟30条；超限事件记为 rate_limited，不执行且不回复。绑定挑战每用户每分钟最多5次；密码复核失败沿用账号锁定保护。

回复与收件箱/请求同事务入队，提交后由当前租约连接发送 `send_private_msg`，使用echo跟踪当前尝试的API回执。失败/超时/重连按当前权限重新生成，最多3次、5分钟，终态清空recipe；不存旧业务结果。回执丢失仍可能重复回复，不承诺恰好一次或对方已读。收件箱/挑战/投递历史的保留和清理策略尚待配置，不能随意清理去重历史。

<a id="onebot-后续范围"></a>

### 后续范围

尚未实现主动连接 OneBot 正向 WebSocket、独立 API/Event 双连接、自由自然语言补充、消息直接落单和 AI。目标会话仍为 idle → parsing → collecting_missing → preview → awaiting_confirmation → executing → completed；等待态允许取消/超时，确认必须绑定参数摘要、当前主体、实例与有效期，执行前重查权限和资源状态。

实际验证包含 ASGI WebSocket、真实回环 TCP WebSocket、PostgreSQL 重复消息并发、Web/消息相同数据范围和字段投影。尚未连接真实 QQ/生产 OneBot 实例，也未验证 Docker/Linux/TLS 环境。

<a id="delivery"></a>

## 回复与连接监控

<a id="delivery-数据关系与边界"></a>

### 数据关系与边界

业务消息、不可变MessageInbox和MessageDelivery在同一authorization_gate事务提交。Delivery.event_key唯一外键指向Inbox；instance_id指向OneBotInstance，owner_id可空指向ERP用户，binding_id/版本成对保存平台绑定快照。重放只查收件箱，不再执行业务或再建Delivery。

OneBotConnection以instance_id唯一关联实例，记录连接UUID、实例配置版本、连接/最后收帧时间、90秒租约、断开时间与固定原因码。仅同一实例的一个未过期连接拥有发送权。新连接只能接管已断开/过期/旧配置版本的记录；旧连接不能续租、收回执或关闭新连接。

| 表                | 核心字段与约束                                                                                                                                                                                                 |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| onebot_connection | id/version/timestamps、唯一instance_id、connection_id、instance_version、state(connected/disconnected)、connected_at、last_seen_at、lease_expires_at、disconnected_at、disconnect_reason                       |
| message_delivery  | id/version/timestamps、唯一event_key、instance_id、recipient_id、可空owner/binding快照、recipe JSON、state、attempts(0..3)、next_attempt_at、expires_at、attempt_token/connection_id、delivered_at、last_error |

新增独立Alembic迁移；不修改旧迁移。已有收件箱不补发，升级只为新事件创建队列。队列/连接数据存在时拒绝破坏性降级。监控资源仅read，通过统一策略和实例id可读关系过滤；recipe、平台收件人、凭据、原始文本、业务结果和连接内部令牌不进入Web监控字段。

<a id="delivery-发送与权限"></a>

### 发送与权限

持久化recipe仅支持query(资源白名单及字符串参数)、operation(请求ID)、固定安全提示。禁止存完整业务回复或原始消息。每次尝试重查实例、连接租约、用户状态、绑定版本及bindings.use，再用相同业务服务的SQL范围/字段投影重新生成查询或当前请求详情；不重新执行采购创建。业务读取权限变化后重新过滤/脱敏；身份或请求授权不足时suppressed并清空recipe。

固定denied/binding_required/unsupported提示不包含业务数据，可在身份失效时安全发送；绑定成功提示要求原绑定仍有效。pending/awaiting_ack最长5分钟、每实例最多1000条非终态、最多3次尝试。发送前先持久化attempt_token与连接UUID，成功发送后等待15秒API回执；失败或超时按5秒/15秒等有界退避重试。重连会接管旧连接未确认任务。终态delivered/failed/suppressed/expired清除recipe。

唯一echo匹配当前尝试及当前连接，且status=ok、retcode为整数0才标记delivered。async/1不算已送达，等待确认/超时；失败码只保存固定原因，不保存模型/平台返回消息。此处delivered仅表示OneBot API成功，不证明QQ用户已读。API缺乏发送幂等键，回执丢失时重试可能重复发送；不承诺恰好一次。

<a id="delivery-运行与可见性"></a>

### 运行与可见性

反向Universal连接内进行有界轮询/发送，不增加Redis/Celery运行依赖。进程退出后的状态由90秒租约失效；服务恢复且OneBot重连后从数据库接续。收帧刷新last_seen，租约定期续期；客户端负责反向重连。断开和旧连接finally处理均需UUID比较，防止误伤新连接。

Web消息接入新增连接监控与回复队列，只读分页/状态筛选，显式新资源授权，不自动扩大旧角色。租约过期展示为失联；失败原因使用固定标签。没有手工强制补发或绕过当前权限的入口。

真实QQ、Linux容器和多进程生产验收仍单独记录；保留/清理与通知outbox消费者不在本阶段范围。

协议依据：[WebSocket](https://github.com/botuniverse/onebot-11/blob/master/communication/ws.md)、[反向连接](https://github.com/botuniverse/onebot-11/blob/master/communication/ws-reverse.md)、[公共API](https://github.com/botuniverse/onebot-11/blob/master/api/public.md)。

<a id="glossary"></a>

## 术语与命令

下表解释当前系统的术语。消息和AI实际可用范围以上文离线指令、OneBot与AI章节为准；命令必须由已验证绑定或Web登录身份执行。

| 术语       | 含义与项目约束                                                     |
| ---------- | ------------------------------------------------------------------ |
| RBAC       | 根据用户拥有的多个角色匹配策略，角色名称本身没有特权               |
| ABAC       | 根据资源属性与条件决定授权，只使用白名单条件 AST                   |
| 数据范围   | 对可访问记录集合施加约束，数据库分页前完成过滤                     |
| 字段投影   | 仅返回允许读取的字段，隐藏字段不进入浏览器、消息或模型             |
| 幂等性     | 重复提交同一命令只产生一次业务效果，主体、幂等键和参数摘要共同约束 |
| Outbox     | 事务内记录待发布事件，发送和消费均可安全重试                       |
| 身份绑定   | 验证平台身份对应的 ERP 用户，QQ 号码本身不能授权                   |
| 确认摘要   | 将规范化参数绑定到用户确认，参数变更需要重新确认                   |
| 审计链     | 每条记录包含前一条摘要，不能独立抵御数据库所有者重写整链           |
| 策略版本   | 不可变规则快照，发布后现有会话下一次请求重新读取                   |
| 审批       | 高风险操作执行前的业务授权，不能扩大申请人的权限                   |
| 解析置信度 | 解析器对意图可信度的估计，高置信度也不能跳过确认和业务校验         |
| 默认拒绝   | 没有明确允许就不执行，新模块不能自动放行                           |
| 拒绝优先   | 命中拒绝策略后，多角色允许不能抵消拒绝                             |
| 乐观版本   | 请求携带读取时版本，旧版本返回冲突，不覆盖其他人的更新             |

<a id="glossary-phase-3-命令设计"></a>

### 常用消息命令

- `/erp 库存 查询 鼠标`：解析商品引用后查询当前用户可见库存。群聊默认不返回敏感信息。
- `/erp 采购 新增 商品=鼠标 数量=20 单价=35`：创建待补充请求，补齐供应商和币种，仓库在实际入库时选择；不会直接创建订单。
- `/erp 确认 请求ID`：提示进入Web密码确认，消息平台不能代替当前ERP密码验证。
- `/erp 取消 请求ID`：取消当前用户的待补充/确认请求，不撤销已完成业务。

库存和采购业务已实现。消息去重防止再次执行业务；回复可能重发，不保证送达或恰好一次。

<a id="glossary-phase-4-可选-ai"></a>

### 可选AI边界

固定命令和本地规则优先，解析失败或置信度不足后，先询问用户是否同意使用 AI。用户拒绝仍可继续使用固定命令。AI 返回的结构化意图须经过严格 schema 校验，不能猜测供应商、金额、审批人或权限。AI 查询工具绑定当前已验证用户，使用相同的数据范围与字段投影，禁止直接执行 SQL。AI 服务离线或失败不能影响非 AI 操作。
