# 实施与验证记录

版本1.0.2为当前开发版本，未创建正式release。

## 当前成果

Phase 0：架构、模块边界、数据关系、权限模型、消息/AI状态机、API规范和AGENTS已建立。

Phase 1基础：真实认证和可撤销会话；组织、多角色；统一RBAC/ABAC、SQL范围过滤、字段权限和状态前后校验；不可变策略发布、冲突提示与模拟；防修改审计链；真实Next.js界面与3D登录。历史策略浏览/恢复、完整审计展示与生产运维仍待完善。

Phase 2采购MVP闭环：分类、商品关联、供应商、仓库；精确十进制草稿/明细；显式提交、独立审批、未收货取消；分批入库、收货单、库存余额与不可变流水；显式币种/无税/独立审批配置；真实Web表单与只读库存查询。订单、明细、收货、流水、余额、幂等记录、outbox与成功审计同事务提交。

当前实现只支持采购入库。没有退货、冲销、汇率换算、含税计算、通用审批工作流、销售和报表。outbox已持久化，尚无消息消费者，不能声称通知已发送。

## 权限与一致性

所有采购入口复用当前会话、授权Gate与同一权限引擎。查询在分页前过滤关联资源；创建与状态动作检查当前权限和目标状态；新增模块不自动修改旧策略。金额字段联动投影，幂等重放重新授权并按当前权限返回已有回执，隐藏ID不参与客户端游标过滤。

独立审批人为默认值。未明确配置币种/无税模式时阻止提交、审批及新的入库；重复请求只查询既有回执。requires_approval策略仍保持拒绝，等待通用审批回执机制完成。基础采购批准不绕过该标志。

5a6ef43a4a48提供采购数据结构；此业务切片未再改数据库结构，alembic check实际报告无遗漏迁移。审计v2记录字段变化及前后版本/摘要，旧v1链保留；422/500等失败先回滚业务再单独记录审计。数据库故障时不能保证审计落盘，只输出脱敏追踪错误。
